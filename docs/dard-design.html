카드 설계 v2

AI 시대에 사용자가 직접 만든 앱을, 일관된 Windows 11 UI의 바탕화면 카드로 담아 주는 구조입니다. 이전 설계(.dard 권한 모델)는 dard-design-v1.html에 남겨 두었습니다.

전제

카드는 사용자가 직접 만들었거나 스스로 믿는 앱입니다. 내가 만든 앱에 내가 허락 버튼을 누르게 하는 것은 모순이므로 권한, 승인, 검증을 두지 않습니다. 앱은 카드가 무엇을 하는지 막지 않고, 카드의 책임은 사용자에게 있습니다.

왜 이 방향인가

  • Windows 가젯은 낡은 기술(ActiveX/COM)이고, Rainmeter는 무겁다.
  • AI가 코드를 만들어 주는 시대라서 "내 앱을 내가 만든다"가 기본 사용 방식이다.
  • MS가 위젯 보드를 샌드박스와 승인 방식으로 만들었지만 외면받았다. 상시 배치와 자유도가 없었기 때문이다.

이 앱이 주는 가치

  • 바탕화면 아이콘 뒤에 고정되는 일관된 카드 틀(아크릴, 둥근 모서리, 편집 모드, 그룹)
  • AI가 아무렇게나 만든 HTML도 Win11처럼 보이게 하는 디자인 키트
  • 보이지 않을 때 멈추는 가벼운 생명주기
남기는 안내 하나: 가져올 때 "이 카드는 PC에 제한 없이 접근해요. 직접 만들었거나 믿는 카드만 쓰세요."를 한 번 보여 줍니다. 권한 체계가 아니라 책임 안내입니다. AI가 쓴 코드를 끝까지 읽지 않는 경우가 있기 때문입니다.

카드 폴더

카드는 폴더입니다. zip 패키지와 해시 검증은 없습니다.

시계\
├─ manifest.json   이름, 처음 크기 등 최소 정보
├─ card.html       화면 (main.py가 있으면 main.py가 직접 내보내도 됨)
├─ main.py         (선택) 백엔드. 로컬 웹서버를 띄움
└─ settings.html   (선택) 카드 우클릭 › 카드 설정으로 여는 화면
{
  "id": "com.example.clock",      // 폴더 이름과 저장 위치에 쓰는 고유 이름
  "name": "시계",
  "size": [200, 200],              // 처음 크기(DIP). 사용자가 자유롭게 바꿀 수 있음
  "background": false              // true면 보이지 않아도 멈추지 않음
}
  • 한 폴더는 카드 하나입니다. 같은 카드를 여러 장 쓰고 싶으면 폴더를 여러 개 두세요.
  • 파일 종류와 크기에 제한이 없습니다. 이미지, 글꼴, 스크립트, data/ 폴더 등 필요한 파일을 폴더에 자유롭게 둡니다.
  • 저장은 백엔드가 카드 폴더의 data/ 같은 실제 파일에 직접 합니다. 앱은 저장소를 관리하지 않습니다.

가져오기

그룹의 카드 만들기에서 가져옵니다. 앱이 카드 폴더를 내부 저장소 %LOCALAPPDATA%\DeskCards\cards\<id>\로 복사하고, 어느 그룹에 속하는지는 앱 설정에 저장합니다.

방법동작
폴더 선택manifest.json이 든 폴더를 고르면 통째로 복사
직접 선택이름, HTML 파일, (선택) Python 파일, 처음 크기, 그룹을 입력창에서 고르면 앱이 manifest를 만들어 줌
zip / .dard카드 폴더를 zip으로 묶은 파일. 가져오면 풀어서 폴더로 만든 뒤에는 폴더만 봄
  • 복사본이라 원본을 고쳐도 반영되지 않습니다. 카드 메뉴에 다시 가져오기와 폴더 열기(내부 폴더)를 둡니다.
  • 연결 모드(개발용): 원본 폴더를 복사하지 않고 그대로 쓰며, 파일이 바뀌면 카드를 새로 고칩니다.
  • 카드를 지우면 내부 저장소의 폴더도 지웁니다. 확인을 한 번 받습니다.
  • 그룹 폴더 안의 .dard 파일을 감시하지 않습니다. 그룹 폴더는 폴더 카드 전용입니다.

실행 구조

앱카드마다 로컬 주소를 정하고 main.py를 실행
→
main.py그 주소에서 웹서버로 HTML과 API를 모두 제공
→
WebView2그 주소를 열어서 카드로 보여 줌
  • desk API는 없습니다. 카드의 HTML이 fetch('/api/cpu')처럼 자기 백엔드와 일반 웹처럼 통신하고, 시스템 정보와 알림, 파일 같은 일은 Python이 알아서 합니다(psutil 등).
  • 카드마다 루프백 IP 하나를 독점합니다. 127.0.0.0/8 전체가 이 PC 자신이므로, 카드 id의 해시로 127.x.y.z를 정하고(127.0.0.1은 제외, 겹치면 다음 주소로 밀어서 설정에 저장), 포트는 흔하지 않은 번호 하나로 고정합니다. 주소가 늘 같아서 origin도 늘 같고, localStorage도 카드별로 저절로 분리됩니다.
  • 고정 포트를 다른 프로그램이 0.0.0.0으로 잡고 있으면 충돌할 수 있어, 바인딩에 실패하면 다른 포트로 다시 시도합니다.
  • 앱은 환경변수 DESK_ADDR, DESK_PORT를 넘기고, 포트가 열릴 때까지 기다린 뒤 WebView를 그 주소로 이동합니다. 시간 안에 안 열리면 카드 안에 오류 화면(로그 보기 포함)을 보여 줍니다.
  • main.py가 없는 카드(HTML만 있는 카드)는 앱이 같은 주소에서 폴더를 정적으로 제공합니다.
  • 토큰, 호스트 검증을 두지 않습니다. 로컬 앱을 신뢰합니다. 감수하는 위험: 사용자가 브라우저에서 연 웹사이트가 카드의 주소와 포트, 경로를 정확히 알고 요청을 보낼 수 있다는 점(확률이 낮음).
  • 현재 개발 구현은 PATH의 Python을 사용합니다. embeddable 번들과 패키지 자동 설치 방식은 후속 결정으로 남깁니다.

생명주기

기존 가시성 결정은 그대로 유지하고, 권한 없이 background 플래그 하나로 줄입니다.

상태동작
카드가 조금이라도 보임백엔드와 화면이 모두 동작
보이지 않음이 5초 지속WebView TrySuspendAsync + 백엔드 프로세스 일시정지. 다시 보이면 곧바로 재개
background: true보이지 않아도 일시정지하지 않음
카드를 지우거나 앱이 종료됨백엔드 프로세스 종료(자식 프로세스까지 정리)
백엔드가 죽음카드에 오류 화면과 [다시 시작]. 자동 재시작은 최대 3회/분

"보이지 않음"의 기준: 최대화·전체화면 창이 그 모니터를 덮음, 카드 바가 닫힘, 화면 잠금. 감지는 SetWinEventHook 이벤트를 0.5초 단위로 모아 처리합니다. Windows 절전 시에는 background 카드도 5초 일시정지 정책의 예외로 두지 않습니다.

디자인 키트

이 앱의 차별점은 보안이 아니라 일관성입니다. AI가 만든 카드도 Win11 앱처럼 보이게 하는 것이 SDK의 실체입니다.

  • 주입 CSS: 앱이 모든 카드 페이지에 desk.css를 넣습니다(기존 테마 변수 주입 방식을 확장). 서버가 무엇을 내보내든 적용됩니다.
    • 토큰: 기존 --desk-fg, --desk-subfg, --desk-accent, --desk-card-bg, --desk-border 등과 간격·모서리·글꼴 크기 토큰
    • 컴포넌트: 버튼, 토글, 슬라이더, 목록 행, 구분선, 제목/본문 글자 스타일 같은 .desk-* 클래스
    • 다크·라이트 자동 전환, 투명 배경(아크릴이 비침), 기본 글꼴 Segoe UI Variable
  • AI용 지침 한 장 (docs/card-guide.md): 카드 폴더 구조, main.py 템플릿(DESK_ADDR/DESK_PORT로 서버 띄우기), 디자인 키트 사용법을 AI에게 그대로 붙여 넣을 수 있게 적습니다. desk.d.ts는 만들지 않습니다.
  • JS API가 없으므로 테마 변경은 CSS 변수와 prefers-color-scheme만으로 전달합니다.

유지하는 것

  • 카드 틀: DWM 둥근 창, 시스템 아크릴, Progman 층(Win+D에도 남음), 편집 모드, 옮기기·스마트 가이드
  • 그룹 카드(폴더 카드) 전체
  • 카드 우클릭 메뉴(카드 설정, 다시 가져오기, 폴더 열기, 삭제)와 설정 창(settings.html)
  • WebView2 복구 정책(BrowserRecoveryPolicy, RendererRecoveryPolicy)
  • 보이지 않을 때 일시정지 모델
  • 가져오기 전 안내 한 번
호환: 기존 .dard 사용자가 없어서 변환 코드는 만들지 않습니다. 앱 업데이트 규약(태그·자산 이름·zip 루트)은 바꾸지 않습니다.

남은 질문

  • Python 번들 방식: 설치기에 포함할지(약 10MB 증가), 처음 필요할 때 내려받을지.
  • 패키지 설치: 카드의 requirements.txt를 가져올 때 앱이 공용 폴더에 pip install 할지, 사용자가 알아서 할지.
  • 절전 모드 — 결정됨: background 카드도 기존 5초 일시정지 정책을 따릅니다.
  • 한 폴더 = 카드 하나 — 결정됨: 새 매니페스트의 id/name/size/background만 사용합니다.
  • 정적 서버 — 구현됨: 앱 내장 TcpListener 서버가 GET/HEAD와 폴더의 자산을 제공합니다.
  • 그룹 폴더 삭제 시 다른 볼륨 처리, 데이터 위치 통일(%APPDATA% / %LOCALAPPDATA%)은 이 설계와 별개로 아직 미정.
