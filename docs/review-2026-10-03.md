# 2026-10-03 코드 리뷰 후 수정

검토 범위는 `a467728..c27ff72`의 오늘 변경 전체다. 실제 사용자 데이터 대신 GUID가 붙은 TEMP 폴더에서 재현했다.

## 수정 내용

- 패키지 id와 카드 id의 결합으로 같은 origin이 만들어지던 문제를 SHA-256/base32 주소와 저장 방식별 레이블로 해결했다. 이름 길이와 무관하게 주소 길이를 제한해 Windows IndexedDB 경로 길이 오류도 피한다.
- 저장소 이전을 원본 내보내기, 대상 가져오기, 완료 기록 저장, 원본 정리 순서로 처리한다. config 저장이 늦거나 옛 백업으로 복구돼도 완료된 대상을 비우지 않는다. 다음 업데이트의 반대 방향 이전도 검증했다.
- 구형 online/offline 주소와 분리 전 WebView2 프로필을 찾아 새 주소로 이전한다. 실패 시 새 빈 저장소로 실행하지 않고 원본과 진행 기록을 보존해 다시 시도한다.
- IndexedDB 자동 증가 키의 상태를 보존한다. 삭제된 높은 키와 중첩 keyPath를 테스트했다. 현재 생성기 값은 [Chrome DevTools Protocol의 IndexedDB.getMetadata](https://chromedevtools.github.io/devtools-protocol/tot/IndexedDB/#method-getMetadata)로 읽는다.
- `__proto__`인 localStorage 키 및 IndexedDB 속성, 유효하지 않은 Date 값을 보존한다.
- 모든 테스트 시작 전에 WebView2 경로를 격리하고 브라우저 환경 캐시도 실제 프로필 경로로 구분한다.
- 손상된 저장소 목록을 빈 목록으로 덮어쓰지 않는다. WebView2 런타임을 사용할 수 없는 상황에서 용량 조회가 비동기 예외로 전파되지 않게 했다.
- 같은 id의 중복 파일 중 하나를 삭제할 때 남은 카드의 승인·위치·데이터를 보존한다. 확인 창이 열린 동안 사라진 경고로 데이터를 지우지 않는다. 마지막 파일 삭제는 이전용 사본과 기록까지 정리한다.
- 저장소 관리 코드를 환경/목록/관리용 화면/이전으로 분리하고 삭제 후 상태 정리를 공통화했다.
- 기존 테스트에서 문서 준비 및 비동기 저장소 이전을 기다리지 않던 부분을 보완했다.

## 검증

화면을 띄우지 않는 신규 회귀 테스트 9개가 통과했다. Debug 테스트 프로젝트와 Release 앱 빌드는 모두 경고·오류 0개다. 최종 전체 회귀 테스트는 64개 통과, 실패 0개, 프로세스 종료 코드 0으로 완료했다. 실제 인터넷 연결 및 내부망 차단 검사도 통과했다. 종료 시 Chromium의 창 클래스 해제 진단(Error 1412)이 출력됐으며 테스트 실패는 없었다.

첫 전체 실행에서 주소 길이와 대기 시점 문제로 5건이 실패해 위 수정에 반영했다. 실제 사용자 환경의 수동 마우스 조작, 다중 모니터 조작 및 실사용 데이터 업그레이드는 수행하지 않았다.
